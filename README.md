# НаучПуть

**НаучПуть** — сервис для поиска научного руководителя по научным интересам, реализованный в формате чат-бота в MAX.

Проект помогает студентам находить преподавателей и исследователей с подходящими научными направлениями, а научным руководителям — получать структурированные заявки от заинтересованных студентов.

Проект разработан как MVP в рамках хакатона.

# О проекте

НаучПуть объединяет в одном сервисе две стороны процесса:

1. студентов, которые ищут научного руководителя;
2. преподавателей и исследователей, готовых руководить студенческими работами.

Вместо ручного поиска по сайтам университетов, кафедрам, публикациям и личным контактам студент заполняет короткий профиль и выбирает интересующее его научное направление.

Система сравнивает его интерес с направлениями зарегистрированных научных руководителей и предлагает подходящего кандидата.

После этого студент может отправить заявку, а научный руководитель — принять или отклонить её.

---

# Проблема

Поиск научного руководителя часто представляет собой неформальный и плохо структурированный процесс.

Студенту необходимо самостоятельно:

- искать преподавателей на сайтах кафедр;
- выяснять научные интересы преподавателей;
- искать контактные данные;
- понимать, готов ли преподаватель брать новых студентов;
- писать преподавателям вручную;
- отслеживать ответы в разных каналах.

При этом преподаватели получают обращения в разных форматах и не всегда имеют удобный способ структурировать входящие запросы.

Это создаёт несколько проблем:

- студент может не знать о подходящем научном руководителе;
- преподаватель может не узнать о заинтересованном студенте;
- поиск зависит от личных знакомств;
- отсутствует единое место для подбора и обработки заявок;
- научные интересы студента и преподавателя сопоставляются вручную.

---

# Решение

НаучПуть предлагает единый сценарий:

```text
Студент
   ↓
Заполнение профиля
   ↓
Выбор научного направления
   ↓
Автоматический подбор
   ↓
Карточка научного руководителя
   ↓
Отправка заявки
   ↓
Решение научного руководителя
   ↓
Статус заявки
```

Вторая сторона системы:

```text
Научный руководитель
   ↓
Заполнение профиля
   ↓
Выбор научного направления
   ↓
Подтверждение университетской почты
   ↓
Получение заявок
   ↓
Принять / отклонить
```

# Целевая аудитория

## Студенты

Студенты бакалавриата, специалитета и магистратуры, которым необходимо найти научного руководителя для:

- курсовой работы;
- выпускной квалификационной работы;
- исследовательского проекта;
- научной статьи;
- участия в лаборатории;

Преподаватели, сотрудники кафедр, лабораторий и исследовательских коллективов, которые готовы работать со студентами.

## Университеты

В дальнейшем система может использоваться университетами как единая площадка распределения студентов по научным руководителям.

# Пользовательские сценарии

## Сценарий студента

### 1. Создание профиля

Студент запускает бота и выбирает роль:

```text
Студент
```

BotHelp последовательно собирает данные профиля.

После завершения анкеты выполняется:

```http
POST /students
```

API создаёт запись в таблице `users`, после чего создаёт связанный профиль в таблице `students`.

API возвращает:

```json
{
  "status": "created",
  "student_id": 1,
  "user_id": 1
}
```

`student_id` сохраняется в пользовательское поле BotHelp и используется в следующих запросах.

---

### 2. Выбор интереса

Студент выбирает категорию и одно научное направление.

Каждому направлению соответствует `interest_id`.

Например:

```text
Машинное обучение → 1
Компьютерное зрение → 3
NLP → 4
Инвестиции → 19
Робототехника → 22
```

После выбора выполняется:

```http
POST /students/{student_id}/interests
```

Пример тела:

```json
{
  "interest_ids": [1]
}
```

---

### 3. Поиск научного руководителя

BotHelp вызывает:

```http
GET /students/{student_id}/matches
```

API находит руководителей с совпадающими интересами.

В BotHelp сохраняются данные первого результата:

```text
supervisor_id
name
university
department
academic_degree
description
matched_interests
```

После этого студент получает карточку научного руководителя.

---

### 4. Отправка заявки

Студент нажимает:

```text
Подать заявку
```

BotHelp вызывает:

```http
POST /applications
```

Пример:

```json
{
  "student_id": 1,
  "supervisor_id": 4,
  "message": "Хочу подать заявку на работу с вами"
}
```

Создаётся заявка со статусом:

```text
pending
```

---

### 5. Просмотр статуса

В главном меню студента есть раздел:

```text
Мои заявки
```

Вызывается:

```http
GET /students/{student_id}/applications
```

Студент видит последнюю заявку:

```text
Научный руководитель
Университет
Кафедра
Учёная степень
Статус
```

Возможные статусы:

```text
pending
accepted
rejected
cancelled
```

# Алгоритм подбора

Matching основан на совпадении научных интересов.

Студент связан с интересами через:

```text
student_interests
```

Руководитель:

```text
supervisor_interests
```

Условно:

```text
Студент
student_id = 10
interest_id = 1

        ↓

research_interests
1 = Машинное обучение

        ↓

Научный руководитель
supervisor_id = 4
interest_id = 1
```

Такой руководитель считается подходящим.

API дополнительно проверяет:

```text
supervisors.is_active = 1
supervisors.available_places > 0
supervisors.email_verified = 1
```

Результаты сортируются по количеству совпавших интересов.

Endpoint:

```http
GET /students/{student_id}/matches
```

# Проверка университетской почты

Email подтверждение используется как дополнительная проверка научного руководителя.

Система использует университет и email, указанные в профиле.

---

## 1. Проверка домена

```http
POST /supervisors/{supervisor_id}/email/check-domain
```

API:

1. получает email пользователя;
2. извлекает домен;
3. определяет университет;
4. проверяет домен в `university_domains`.

---

## 2. Отправка кода

```http
POST /supervisors/{supervisor_id}/email/send-code
```

Генерируется шестизначный код.

Код сохраняется в:

```text
email_verification_codes
```

Срок действия:

```text
10 минут
```

Письмо отправляется через:

```text
smtp.yandex.ru
порт 465
SMTP_SSL
```

---

## 3. Проверка кода

```http
POST /supervisors/{supervisor_id}/email/verify-code
```

Пример:

```json
{
  "code": "123456"
}
```

После успешной проверки:

```text
email_verified = 1
verified_at = current timestamp
```

# Особенность SMTP в демонстрационном окружении

Локально Yandex SMTP работает напрямую:

```text
FastAPI
   ↓
smtp.yandex.ru:465
```

В бесплатном окружении Render исходящие SMTP-соединения ограничены.

Поэтому для демонстрации отправки email используется:

```text
Cloudflare Quick Tunnel
        ↓
локальный FastAPI
        ↓
Yandex SMTP
```

Например:

```text
BotHelp
↓
https://<temporary>.trycloudflare.com
↓
localhost:8000
↓
smtp.yandex.ru
```

При этом остальные API-запросы могут обслуживаться публичным backend на Render.

# Интеграция с BotHelp

BotHelp используется как визуальный workflow-движок.

Он выполняет:

```text
получение данных пользователя
сохранение переменных
ветвление
работу кнопок
HTTP-запросы
обработку JSON
вывод результатов
```

---

## Пример создания студента

BotHelp собирает:

```text
name
university
faculty
course
description
desired_topic
photo
```

Затем отправляет:

```http
POST /students
```

Из ответа сохраняется:

```text
$.student_id → student_id
```

## Пример matching

BotHelp вызывает:

```http
GET /students/{student_id}/matches
```

Сопоставление:

```text
$.matches[0].supervisor_id
→ matched_supervisor_id

$.matches[0].name
→ matched_supervisor_name

$.matches[0].university
→ matched_supervisor_university

$.matches[0].department
→ matched_supervisor_department

$.matches[0].academic_degree
→ matched_supervisor_degree

$.matches[0].description
→ matched_supervisor_description

$.matches[0].matched_interests
→ matched_interests
```

# Полный демонстрационный тест

Для проверки основного сценария используются два аккаунта.

1. Запустить бота.

3. Заполнить профиль.
4. Выбрать научный интерес.
5. Убедиться, что профиль появился в MySQL.

## Научный руководитель

6. Запустить бота со второго аккаунта.
7. Выбрать роль научного руководителя.
8. Заполнить профиль.
9. Выбрать тот же интерес.
10. Подтвердить университетскую почту.

## Matching

11. Вернуться к студенту.
12. Нажать «Найти научного руководителя».
13. Убедиться, что руководитель найден.

## Заявка

14. Нажать «Подать заявку».
15. Проверить появление записи в `applications`.

## Руководитель

16. Открыть «Мои заявки».
17. Убедиться, что отображается заявка студента.
18. Нажать «Принять».

## Студент

19. Открыть «Мои заявки».
20. Убедиться, что:

```text
status = accepted
```

# Потенциал масштабирования

Текущая архитектура не привязана к одному университету.

Для подключения нового университета достаточно:

1. добавить университет;
2. добавить его официальные email-домены;
3. зарегистрировать научных руководителей;
4. добавить необходимые научные направления.

Это позволяет потенциально использовать НаучПуть как межвузовскую платформу.

# Почему выбран чат-бот

Формат чат-бота снижает порог входа:

```text
не требуется устанавливать отдельное приложение
нет сложного интерфейса
регистрация проходит последовательно
весь процесс проходит в привычном мессенджере
```

BotHelp позволяет быстро менять пользовательские сценарии, а бизнес-логика при этом остаётся в отдельном FastAPI backend.
