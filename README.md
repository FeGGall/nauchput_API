# НаучПуть

**НаучПуть** — чат-бот в MAX для поиска научного руководителя по научным интересам студента.

Сервис помогает студенту заполнить профиль, выбрать интересующее научное направление, получить подходящего научного руководителя и отправить ему заявку. Научный руководитель может зарегистрироваться, подтвердить университетскую электронную почту, указать научное направление и принимать или отклонять заявки студентов.

---

# 1. Назначение решения

Поиск научного руководителя часто происходит неструктурированно: через кафедры, знакомых, списки преподавателей и личные сообщения.

Цель «НаучПути» — создать единый простой сценарий внутри MAX:

1. студент создаёт профиль;
2. указывает научный интерес;
3. система автоматически подбирает подходящего научного руководителя;
4. студент отправляет заявку;
5. научный руководитель принимает или отклоняет её;
6. студент видит статус заявки.

В текущей MVP-версии подбор выполняется по совпадению научных интересов.

---

# 2. Основной пользовательский сценарий

## Студент

Студент:

1. запускает чат-бота «НаучПуть» в MAX;
2. выбирает роль **«Студент»**;
3. заполняет анкету:
   - ФИО;
   - университет;
   - факультет;
   - курс;
   - описание;
   - желаемую тему исследования;
   - фотографию;
4. выбирает научный интерес;
5. профиль сохраняется в базе данных;
6. студент нажимает **«Найти научного руководителя»**;
7. API ищет доступных научных руководителей с совпадающим научным интересом;
8. студент получает анкету подходящего руководителя;
9. нажимает **«Подать заявку»**;
10. заявка создаётся со статусом `pending`;
11. студент может открыть раздел **«Мои заявки»** и посмотреть её статус.

Возможные статусы:

- `pending` — ожидает решения;
- `accepted` — заявка принята;
- `rejected` — заявка отклонена;
- `cancelled` — заявка отменена.

---

## Научный руководитель

Научный руководитель:

1. запускает чат-бота;
2. выбирает роль **«Научный руководитель»**;
3. заполняет профиль:
   - ФИО;
   - университет;
   - кафедру;
   - академическую степень;
   - описание;
   - электронную почту;
   - фотографию;
4. указывает научный интерес;
5. вводит университетскую электронную почту;
6. система проверяет соответствие домена электронной почты выбранному университету;
7. на почту отправляется шестизначный код;
8. пользователь вводит код в чат-боте;
9. после успешной проверки профиль становится доступен для подбора студентам;
10. научный руководитель открывает раздел **«Мои заявки»**;
11. просматривает анкету студента;
12. принимает или отклоняет заявку.

При принятии заявки количество доступных мест у научного руководителя уменьшается на одно.

## Компоненты

### MAX

Основной пользовательский интерфейс решения.

Через MAX пользователь:

- проходит регистрацию;
- заполняет профиль;
- выбирает интерес;
- ищет научного руководителя;
- отправляет заявку;
- просматривает заявки;
- принимает или отклоняет заявки.

### BotHelp

Используется как конструктор сценариев чат-бота.

BotHelp:

- хранит промежуточные пользовательские переменные;
- управляет ветвлением диалогов;
- отправляет HTTP-запросы в FastAPI;
- сохраняет значения из JSON-ответов API.

### FastAPI

Собственный backend проекта.

FastAPI отвечает за:

- создание пользователей;
- создание профилей студентов;
- создание профилей научных руководителей;
- сохранение научных интересов;
- подбор научных руководителей;
- работу с заявками;
- проверку университетских email-доменов;
- отправку кодов подтверждения;
- проверку кодов подтверждения.

### MySQL

Основное постоянное хранилище данных.

В рабочей версии используется MySQL на Beget.

### Render

Используется для публичного размещения FastAPI.

Рабочий адрес API:

```text
https://nauchput-api.onrender.com
```

### Cloudflare Quick Tunnel

Используется только для демонстрационного обходного сценария отправки email с локальной машины.

Бесплатное окружение Render ограничивает исходящие SMTP-подключения, поэтому отправка кода подтверждения может выполняться через локально запущенный FastAPI, доступный через временный Cloudflare Tunnel.

Cloudflare Tunnel не является обязательной частью основной бизнес-логики сервиса и используется только для демонстрации email-верификации.

### Yandex SMTP

Используется для отправки шестизначного кода подтверждения университетской электронной почты.

# 13. Алгоритм подбора научного руководителя

Студент выбирает научный интерес.

API ищет руководителей, которые:

```text
имеют тот же научный интерес
AND is_active = 1
AND available_places > 0
AND email_verified = 1
```

Результаты сортируются по количеству совпавших интересов.

В текущей версии BotHelp показывает первый подходящий результат:

```text
matches[0]
```

# 16. Проверка университетской электронной почты

Проверка состоит из трёх этапов.

## Проверка домена

```text
POST /supervisors/{supervisor_id}/email/check-domain
```

Система:

1. получает email пользователя;
2. извлекает домен;
3. находит выбранный университет;
4. проверяет домен в `university_domains`.

---

## Отправка кода

```text
POST /supervisors/{supervisor_id}/email/send-code
```

Генерируется шестизначный код.

Пример:

```text
042731
```

Код сохраняется в базе и отправляется на email пользователя.

---

## Проверка кода

```text
POST /supervisors/{supervisor_id}/email/verify-code
```

Пример тела:

```json
{
  "code": "042731"
}
```

При успешной проверке:

```text
email_verified = 1
```

После этого научный руководитель может участвовать в подборе.


# 26. Email-верификация при локальной демонстрации

На бесплатном окружении Render исходящие SMTP-соединения могут быть недоступны.

Для демонстрации email-подтверждения можно запустить API локально.

Первый терминал:

```bash
python -m uvicorn nauchput_API:app --host 127.0.0.1 --port 8000
```

Второй терминал:

```bash
cloudflared tunnel --url http://localhost:8000
```

Cloudflare создаст временный HTTPS URL.

Для демонстрационного сценария endpoint отправки email может вызываться через этот адрес.

Важно:

- локальный FastAPI должен оставаться запущенным;
- Cloudflare Tunnel должен оставаться запущенным;
- URL Quick Tunnel меняется после перезапуска.

# 30. Известные ограничения MVP

Текущая версия является MVP.

Основные ограничения:

1. пользователь выбирает один основной научный интерес;
2. BotHelp отображает первый результат из списка совпадений;
3. отсутствует полноценная система рекомендаций на основе ML;
4. отсутствует ранжирование по истории взаимодействия пользователей;
5. отсутствует веб-панель администратора;
6. используется общий серверный `X-API-Key`, а не отдельная пользовательская API-аутентификация;
7. email-верификация зависит от доступности внешнего SMTP;
8. Cloudflare Quick Tunnel используется только как временный демонстрационный механизм;
9. URL Quick Tunnel меняется после перезапуска;
10. фотографии хранятся в виде внешних URL;
11. часть внешних сервисов — MAX, BotHelp, Render, Beget и SMTP — не воспроизводится внутри Docker;
12. при отсутствии подтверждённой университетской почты научный руководитель не участвует в подборе.
